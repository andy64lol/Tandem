# 2. Getting started

## Prerequisites

Install Rust and a working C build toolchain. The C toolchain builds the vendored Lua 5.4 runtime.

## Build

From the project directory:

```sh
cargo build --release
```

This creates `target/release/typelua`.

## Compile and run a program

TypeLua source files use the `.tlua` extension. Compilation writes a `.lua` file next to the source and then executes it:

```sh
cargo run -- examples/hello.tlua
#    Compiling examples/hello.tlua
#     Finished examples/hello.lua
```

Or invoke the compiled binary directly:

```sh
./target/release/typelua examples/hello.tlua
```

Choose another output path by passing it as the second argument; the output directory must already exist:

```sh
cargo run -- examples/hello.tlua build/hello.lua
```

Before compiling, TypeLua checks the output path. An existing `.lua` file is overwritten only if it starts with the TypeLua-generated header (`-- Generated by TypeLua ...`); otherwise the command refuses to overwrite it. This prevents generated output from replacing hand-written Lua files.

## Check without running

`--check` parses and type-checks the file without writing or executing any Lua. On success it prints the path:

```sh
cargo run -- --check examples/hello.tlua
#     Checking examples/hello.tlua
#     Finished examples/hello.tlua
```

To install dependencies declared in `mlua-pkg.toml`, run `typelua pkg install` from the project directory. See [LuaRocks packages](10-cli.md#luarocks-packages) for the manifest format and runtime behavior.

## Split a program across files

Use `require` with Lua's calling syntax. Module paths use `/` and, preferably, an explicit `.tlua` or `.lua` extension:

```tlua
module greetings = require("greetings.tlua");
module helper = require("lua-helper.lua");

print(greetings.hello("Lua"));
print(helper.hello("Lua"));
```

The `module` type declares a binding whose type is inferred from the required file. The Lua-style forms are also supported:

```tlua
local greetings = require("greetings.tlua");
print(require("greetings.tlua").hello("Lua"));
```

A path without an extension is resolved as `<path>.tlua`, then `<path>.lua`, then `<path>/init.tlua` and `<path>/init.lua`, relative to the main input file's directory. Lua-style dotted names such as `lib.math` also resolve to `lib/math.tlua` and the other candidates, for compatibility with Lua packages. Paths beginning with `./` or `../` are treated as explicit relative paths.

Every `.tlua` module reached through `require` is compiled and embedded into the generated Lua under `package.preload`. `.lua` modules are not compiled: they are loaded by Lua at runtime from the input file's directory. Their values are typed dynamically, so use `as type` when assigning them to statically typed variables. A module that is not found locally is left to Lua's package system, such as modules installed with `typelua pkg install`. A missing path with an explicit extension or an explicit `./`/`../` prefix is a compile error.

As in Lua, a standalone `require("greetings.tlua");` only loads the module and does not create a variable. Bind the result with `module name = require("...");` or `local name = require("...");` to use its exports.

See [`examples/modules.tlua`](../examples/modules.tlua) for a program that imports both a TypeLua module and a Lua module.

## Import the standard library

Lua's standard library packages are not in scope by default. Import the packages a program uses at the top level, then access their members:

```tlua
import string, math;

str upper = string.upper("lua") as str;
float root = math.sqrt(16.0) as float;
```

Members of imported packages are dynamic, so an `as type` assertion is needed when assigning one to a typed variable. Lua's base functions such as `tostring` and `pairs` need `import base;`. See [Expressions](07-expressions.md#standard-library-imports) for the full list.

## Run ordinary Lua files

Pass a `.lua` file to execute it directly in the embedded runtime. Extra arguments reach the script through Lua's `arg` table:

```sh
cargo run -- examples/script.lua first-arg second-arg
```

See [Command line](10-cli.md) for the full CLI reference, including error handling and exit codes.
