# 10. Command line

## LuaRocks packages

TypeLua uses `mlua-pkg` to install pure-Lua LuaRocks packages from their Git repositories. Add a manifest to the project directory:

```toml
[package]
name = "my-project"
version = "0.1.0"

[deps]
penlight = { git = "https://github.com/lunarmodules/Penlight", tag = "1.14.0" }
```

Then run:

```sh
typelua pkg install
```

At runtime, TypeLua loads installed modules from `mlua-pkg.lock`. For example, `require("pl.path")` resolves Penlight's path module. Package dependencies are pinned in the lockfile. `mlua-pkg` reads rockspecs from Git repositories; it does not look packages up by name on luarocks.org, and C modules are not built as part of installation.

## Synopsis

```
typelua [--memory-limit <bytes>] [--instruction-limit <count>] <input.tlua|script.lua> [output.lua or script arguments...]
typelua [--memory-limit <bytes>] [--instruction-limit <count>] --check <input.tlua>
typelua --version
typelua pkg install [project-dir]
```

The limit flags apply to embedded Lua execution, including the run step after a `.tlua` file is compiled.

## Build

Install Rust and a working C build toolchain, then build the compiler and its embedded Lua 5.4 runtime from the project directory:

```sh
cargo build --release
```

This creates `target/release/typelua`. The Lua runtime is built through the `mlua` dependency with vendored Lua, so a separate `lua` executable is not required.

## Compile and run TypeLua source

TypeLua source files use the `.tlua` extension. Compilation writes a `.lua` file next to the source and then executes it:

```sh
typelua examples/hello.tlua
#    Compiling examples/hello.tlua
#     Finished examples/hello.lua
Hello, world!
```

Choose another output path by passing it as the second argument:

```sh
typelua examples/hello.tlua build/hello.lua
```

The output directory must already exist. Before compiling, TypeLua checks the target path: an existing `.lua` file is overwritten only when it starts with the generated header (`-- Generated by TypeLua ...`). If the file was not generated by TypeLua, the command fails instead of replacing it.

When developing in this repository, use Cargo to run the CLI:

```sh
cargo run -- examples/hello.tlua
cargo run -- examples/hello.tlua examples/hello-custom.lua
```

`require` follows the module graph. Paths use `/` and may include an explicit `.tlua` or `.lua` extension. Without an extension, TypeLua tries `<path>.tlua`, `<path>.lua`, `<path>/init.tlua`, and `<path>/init.lua` relative to the input file's directory. Lua-style dotted names such as `lib.math` also resolve to `lib/math.tlua` and the other candidates. Every `.tlua` file reached from the input is compiled and embedded in the generated Lua under `package.preload`. Imported `.lua` files are not compiled or copied; they are loaded by Lua at runtime from the input file's directory. `--check` parses and checks the same set of files.

## Check without running

`--check` parses and type-checks the file. It does not write or execute generated Lua, and on success prints the checked path:

```sh
typelua --check examples/hello.tlua
#     Checking examples/hello.tlua
#     Finished examples/hello.tlua
cargo run -- --check examples/hello.tlua
```

## Run ordinary Lua files

Pass a `.lua` file to execute it directly in the embedded Lua 5.4 runtime. Additional arguments are available to the script through Lua's `arg` table (`arg[0]` is the path, and script arguments start at `arg[1]`):

```sh
typelua examples/script.lua first-arg second-arg
cargo run -- examples/script.lua first-arg second-arg
```

The `.lua` file is run as written; it is not parsed as TypeLua or transpiled.

## Runtime limits

Two flags bound execution of Lua code. They may appear before the input path:

```sh
typelua --instruction-limit 1000000 script.lua
typelua --memory-limit 67108864 script.lua
```

- `--instruction-limit <count>` aborts execution after roughly the given number of Lua VM instructions. It is a guard against infinite loops, not a precise time limit; the runtime checks in batches of at most 10,000 instructions.
- `--memory-limit <bytes>` sets the Lua allocator limit. Allocation beyond this limit fails with a Lua memory error.

Both failures are reported as Lua runtime errors after any TypeLua output file has been written, and the command exits with status 1.

## Diagnostics

Source and Lua runtime errors are printed to standard error, and the command exits with a nonzero status:

- A TypeLua diagnostic (error or warning) is printed as `error: ...` or `warning: ...`, followed by a ` --> path:line:column` line when the location is known. Because warnings are fatal, either form prevents output generation and exits with status 1. See [Diagnostics](09-diagnostics.md).
- A Lua runtime error happens after the output file has been written, so the generated file remains available for inspection. The command exits with status 1.
- An invalid command line prints the usage message and exits with status 2.

Status labels and diagnostics use ANSI colors when the corresponding stream is a terminal; piped output stays plain text.

Generated Lua also contains `-- tlua:<line>:<column>` comments that map statements back to the TypeLua source; see [Diagnostics](09-diagnostics.md#source-maps).

On success the command exits with status 0.
