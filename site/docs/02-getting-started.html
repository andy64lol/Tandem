2. Getting started

Prerequisites

Install Rust and a working C build toolchain. The C toolchain builds the vendored Lua 5.4 runtime.

Build

From the project directory:

cargo build --release

This creates target/release/tandem.

Compile and run a program

Tandem source files use the .tdm extension. Compilation writes a .lua file next to the source and then executes it:

cargo run -- examples/hello.tdm
#    Compiling examples/hello.tdm
#     Finished examples/hello.lua

Or invoke the compiled binary directly:

./target/release/tandem examples/hello.tdm

Choose another output path by passing it as the second argument; the output directory must already exist:

cargo run -- examples/hello.tdm build/hello.lua

Before compiling, Tandem checks the output path. An existing .lua file is overwritten only if it starts with the Tandem-generated header (-- Generated by Tandem ...); otherwise the command refuses to overwrite it. This prevents generated output from replacing hand-written Lua files.

Check without running

--check parses and type-checks the file without writing or executing any Lua. On success it prints the path:

cargo run -- --check examples/hello.tdm
#     Checking examples/hello.tdm
#     Finished examples/hello.tdm

To install dependencies declared in mlua-pkg.toml, run tandem pkg install from the project directory. See LuaRocks packages for the manifest format and runtime behavior.

Split a program across files

Use require with Lua's calling syntax. Module paths use / and, preferably, an explicit .tdm or .lua extension:

module greetings = require("greetings.tdm");
module helper = require("lua-helper.lua");

print(greetings.hello("Lua"));
print(helper.hello("Lua"));

The module type declares a binding whose type is inferred from the required file. The Lua-style forms are also supported:

local greetings = require("greetings.tdm");
print(require("greetings.tdm").hello("Lua"));

A path without an extension is resolved as <path>.tdm, then <path>.lua, then <path>/init.tdm and <path>/init.lua, relative to the main input file's directory. Lua-style dotted names such as lib.math also resolve to lib/math.tdm and the other candidates, for compatibility with Lua packages. Paths beginning with ./ or ../ are treated as explicit relative paths.

Every .tdm module reached through require is compiled and embedded into the generated Lua under package.preload. .lua modules are not compiled: they are loaded by Lua at runtime from the input file's directory. Their values are typed dynamically, so use as type when assigning them to statically typed variables. A module that is not found locally is left to Lua's package system, such as modules installed with tandem pkg install. A missing path with an explicit extension or an explicit .//../ prefix is a compile error.

As in Lua, a standalone require("greetings.tdm"); only loads the module and does not create a variable. Bind the result with module name = require("..."); or local name = require("..."); to use its exports.

See examples/modules.tdm for a program that imports both a Tandem module and a Lua module.

Import the standard library

Lua's standard library packages are not in scope by default. Import the packages a program uses at the top level, then access their members:

import string, math;

str upper = string.upper("lua") as str;
float root = math.sqrt(16.0) as float;

Members of imported packages are dynamic, so an as type assertion is needed when assigning one to a typed variable. Lua's base functions such as tostring and pairs need import base;. See Expressions for the full list.

Run ordinary Lua files

Pass a .lua file to execute it directly in the embedded runtime. Extra arguments reach the script through Lua's arg table:

cargo run -- examples/script.lua first-arg second-arg

See Command line for the full CLI reference, including error handling and exit codes.
