10. Línea de comandos

Paquetes LuaRocks

Tandem usa mlua-pkg para instalar paquetes LuaRocks puros desde sus repositorios Git. Añade un manifiesto al directorio del proyecto:

[package]
name = "my-project"
version = "0.1.0"

[deps]
penlight = { git = "https://github.com/lunarmodules/Penlight", tag = "1.14.0" }

Luego ejecuta:

tandem pkg install

En tiempo de ejecución, Tandem carga los módulos instalados desde mlua-pkg.lock. Por ejemplo, require("pl.path") resuelve el módulo path de Penlight. Las dependencias de paquetes se fijan en el lockfile. mlua-pkg lee rockspecs de los repositorios Git; no busca paquetes por nombre en luarocks.org y los módulos C no se compilan como parte de la instalación.

Sinopsis

tandem [--memory-limit <bytes>] [--instruction-limit <count>] [--sandbox] [--target <lua5.1|lua5.2|lua5.3|lua5.4>] <input.tdm|script.lua> [output.lua o argumentos del script...]
tandem [opciones] --check <input.tdm>
tandem --version
tandem fmt <input.tdm>
tandem repl
tandem lsp
tandem dap
tandem new <name>
tandem build
tandem run [--watch] [argumentos del script...]
tandem test [input.tdm]
tandem coverage [input.tdm]
tandem profile [input.tdm]
tandem add <name> [git-url] [--tag <tag>]
tandem pkg install [project-dir]

Los flags de límite se aplican a la ejecución de Lua embebido, incluido el paso de ejecución después de compilar un archivo .tdm.

Compilar y ejecutar código fuente Tandem

Los archivos fuente de Tandem usan la extensión .tdm. La compilación escribe un archivo .lua junto al fuente y luego lo ejecuta:

tandem examples/hello.tdm
#    Compiling examples/hello.tdm
#     Finished examples/hello.lua
Hello, world!

Elige otra ruta de salida pasándola como segundo argumento:

tandem examples/hello.tdm build/hello.lua

El directorio de salida ya debe existir. Antes de compilar, Tandem comprueba la ruta objetivo: un archivo .lua existente se sobrescribe solo cuando empieza con la cabecera generada (-- Generated by Tandem ...). Si el archivo no fue generado por Tandem, el comando falla en lugar de reemplazarlo.

Al desarrollar en este repositorio, usa Cargo para ejecutar la CLI:

cargo run -- examples/hello.tdm
cargo run -- examples/hello.tdm examples/hello-custom.lua

require sigue el grafo de módulos. Las rutas usan / y pueden incluir una extensión explícita .tdm o .lua. Sin extensión, Tandem intenta <path>.tdm, <path>.lua, <path>/init.tdm y <path>/init.lua relativos al directorio del archivo de entrada. Los nombres punteados estilo Lua como lib.math también resuelven a lib/math.tdm y a los otros candidatos. Cada archivo .tdm alcanzado desde la entrada se compila e incrusta en el Lua generado bajo package.preload. Los archivos .lua importados no se compilan ni copian; Lua los carga en tiempo de ejecución desde el directorio del archivo de entrada. --check analiza y comprueba el mismo conjunto de archivos.

Comprobar sin ejecutar

--check analiza y comprueba los tipos del archivo. No escribe ni ejecuta el Lua generado y, en caso de éxito, imprime la ruta comprobada:

tandem --check examples/hello.tdm
#     Checking examples/hello.tdm
#     Finished examples/hello.tdm
cargo run -- --check examples/hello.tdm

Ejecutar archivos Lua ordinarios

Pasa un archivo .lua para ejecutarlo directamente en el runtime Lua 5.4 embebido. Los argumentos adicionales están disponibles para el script a través de la tabla arg de Lua (arg[0] es la ruta y los argumentos del script empiezan en arg[1]):

tandem examples/script.lua first-arg second-arg
cargo run -- examples/script.lua first-arg second-arg

El archivo .lua se ejecuta tal cual; no se analiza como Tandem ni se transpila.

Límites de runtime

Dos flags acotan la ejecución de código Lua. Pueden aparecer antes de la ruta de entrada:

tandem --instruction-limit 1000000 script.lua
tandem --memory-limit 67108864 script.lua
tandem --sandbox script.lua
  • --instruction-limit <count> aborta la ejecución después de aproximadamente el número dado de instrucciones de la VM de Lua. Es una protección contra bucles infinitos, no un límite de tiempo preciso; el runtime comprueba en lotes de como máximo 10,000 instrucciones.
  • --memory-limit <bytes> establece el límite del asignador de Lua. La asignación más allá de este límite falla con un error de memoria de Lua.
  • --sandbox restringe la biblioteca estándar a un subconjunto pequeño y sin efectos secundarios, eliminando io, os, debug, package, require y funciones relacionadas.

Ambos fallos se reportan como errores de runtime de Lua después de que cualquier archivo de salida de Tandem se haya escrito, y el comando sale con estado 1.

Diagnósticos

Los errores de fuente y de runtime de Lua se imprimen en el error estándar y el comando sale con un estado distinto de cero:

  • Un diagnóstico de Tandem (error o advertencia) se imprime como error: ... o warning: ..., seguido de una línea --> path:line:column cuando se conoce la ubicación. Como las advertencias son fatales, cualquiera de las dos formas impide la generación de salida y sale con estado 1. Consulta Diagnósticos.
  • Un error de runtime de Lua ocurre después de que el archivo de salida se haya escrito, por lo que el archivo generado sigue disponible para inspección. El comando sale con estado 1.
  • Una línea de comandos inválida imprime el mensaje de uso y sale con estado 2.

Las etiquetas de estado y los diagnósticos usan colores ANSI cuando el flujo correspondiente es una terminal; la salida redirigida permanece en texto plano.

El Lua generado también contiene comentarios -- tdm:<line>:<column> que mapean sentencias de vuelta al código fuente de Tandem; consulta Diagnósticos.

En caso de éxito el comando sale con estado 0.

Proyectos

tandem new <name> crea un nuevo directorio de proyecto con tandem.config, src/main.tdm y una plantilla de programa.

tandem build compila el punto de entrada del proyecto (src/main.tdm o src/lib.tdm) en target/debug/<name>.lua. Usa --target lua5.1|lua5.2|lua5.3|lua5.4 para generar Lua para otro intérprete; la salida se escribe en target/<target>/debug/. Las compilaciones incrementales reutilizan el resultado cuando las fuentes no han cambiado.

tandem run compila y ejecuta. Añade --watch para recompilar y re-ejecutar automáticamente cuando cambien los archivos .tdm. Los argumentos adicionales se pasan al programa a través de la tabla arg.

tandem test [input.tdm] compila y ejecuta los bloques test "name" { ... } embebidos, imprimiendo el resultado de cada uno y saliendo con estado distinto de cero si alguno falla.

tandem coverage [input.tdm] y tandem profile [input.tdm] compilan y ejecutan el programa mientras registran qué líneas de Tandem se ejecutaron y cuánto tiempo pasó en cada una.

tandem dap inicia un adaptador del protocolo de depuración (DAP) sobre stdin/stdout, con puntos de interrupción mapeados de vuelta a las líneas de Tandem.

tandem fmt <input.tdm> formatea un archivo fuente en su lugar.

tandem add <name> [git-url] [--tag <tag>] añade una dependencia git a tandem.config (resolviendo nombres simples contra TANDEM_REGISTRY, por defecto https://github.com) e instala el paquete.

tandem pkg install [project-dir] instala las dependencias declaradas en tandem.config.
