10. Command line

LuaRocks packages

Tandem uses mlua-pkg to install pure-Lua LuaRocks packages from their Git repositories. Add a manifest to the project directory:

[package]
name = "my-project"
version = "0.1.0"

[deps]
penlight = { git = "https://github.com/lunarmodules/Penlight", tag = "1.14.0" }

Then run:

tandem pkg install

At runtime, Tandem loads installed modules from mlua-pkg.lock. For example, require("pl.path") resolves Penlight's path module. Package dependencies are pinned in the lockfile. mlua-pkg reads rockspecs from Git repositories; it does not look packages up by name on luarocks.org, and C modules are not built as part of installation.

Synopsis

tandem [--memory-limit <bytes>] [--instruction-limit <count>] <input.tdm|script.lua> [output.lua or script arguments...]
tandem [--memory-limit <bytes>] [--instruction-limit <count>] --check <input.tdm>
tandem --version
tandem pkg install [project-dir]

The limit flags apply to embedded Lua execution, including the run step after a .tdm file is compiled.

Build

Install Rust and a working C build toolchain, then build the compiler and its embedded Lua 5.4 runtime from the project directory:

cargo build --release

This creates target/release/tandem. The Lua runtime is built through the mlua dependency with vendored Lua, so a separate lua executable is not required.

Compile and run Tandem source

Tandem source files use the .tdm extension. Compilation writes a .lua file next to the source and then executes it:

tandem examples/hello.tdm
#    Compiling examples/hello.tdm
#     Finished examples/hello.lua
Hello, world!

Choose another output path by passing it as the second argument:

tandem examples/hello.tdm build/hello.lua

The output directory must already exist. Before compiling, Tandem checks the target path: an existing .lua file is overwritten only when it starts with the generated header (-- Generated by Tandem ...). If the file was not generated by Tandem, the command fails instead of replacing it.

When developing in this repository, use Cargo to run the CLI:

cargo run -- examples/hello.tdm
cargo run -- examples/hello.tdm examples/hello-custom.lua

require follows the module graph. Paths use / and may include an explicit .tdm or .lua extension. Without an extension, Tandem tries <path>.tdm, <path>.lua, <path>/init.tdm, and <path>/init.lua relative to the input file's directory. Lua-style dotted names such as lib.math also resolve to lib/math.tdm and the other candidates. Every .tdm file reached from the input is compiled and embedded in the generated Lua under package.preload. Imported .lua files are not compiled or copied; they are loaded by Lua at runtime from the input file's directory. --check parses and checks the same set of files.

Check without running

--check parses and type-checks the file. It does not write or execute generated Lua, and on success prints the checked path:

tandem --check examples/hello.tdm
#     Checking examples/hello.tdm
#     Finished examples/hello.tdm
cargo run -- --check examples/hello.tdm

Run ordinary Lua files

Pass a .lua file to execute it directly in the embedded Lua 5.4 runtime. Additional arguments are available to the script through Lua's arg table (arg[0] is the path, and script arguments start at arg[1]):

tandem examples/script.lua first-arg second-arg
cargo run -- examples/script.lua first-arg second-arg

The .lua file is run as written; it is not parsed as Tandem or transpiled.

Runtime limits

Two flags bound execution of Lua code. They may appear before the input path:

tandem --instruction-limit 1000000 script.lua
tandem --memory-limit 67108864 script.lua
  • --instruction-limit <count> aborts execution after roughly the given number of Lua VM instructions. It is a guard against infinite loops, not a precise time limit; the runtime checks in batches of at most 10,000 instructions.
  • --memory-limit <bytes> sets the Lua allocator limit. Allocation beyond this limit fails with a Lua memory error.

Both failures are reported as Lua runtime errors after any Tandem output file has been written, and the command exits with status 1.

Diagnostics

Source and Lua runtime errors are printed to standard error, and the command exits with a nonzero status:

  • A Tandem diagnostic (error or warning) is printed as error: ... or warning: ..., followed by a --> path:line:column line when the location is known. Because warnings are fatal, either form prevents output generation and exits with status 1. See Diagnostics.
  • A Lua runtime error happens after the output file has been written, so the generated file remains available for inspection. The command exits with status 1.
  • An invalid command line prints the usage message and exits with status 2.

Status labels and diagnostics use ANSI colors when the corresponding stream is a terminal; piped output stays plain text.

Generated Lua also contains -- tdm:<line>:<column> comments that map statements back to the Tandem source; see Diagnostics.

On success the command exits with status 0.
